# src/templates — canned starter projects

Templates are plain project DOCUMENTS built at module load (builder currently stamps `schemaVersion: 8` — keep it in step with document-shape changes, since `ProjectStore.applyTemplate(tpl.document)` consumes the document directly). Start points from the projects page, or account-free demos via `/editor?template=<id>`. `applyTemplate` copies the template's non-main scene into the CURRENT scene, remints every id (safe to re-apply), keeps audio tracks, and lets a loaded song's BPM win over the template's — one `set()`, one undo step.

- `library.ts` — `TemplateDef` shape; `index.ts` — the list (`TEMPLATES`). Adding a template = one `library-<name>.ts` volume + one entry in `index.ts`; nothing else hardcodes the list. Lyric templates lead the ordering (the product's wedge).
- `builder.ts` — authoring helpers (`n()` notes, `pulse()`, track/block constructors). Ids are readable counters (`tpl-…`), unique per document only — fine because rows are independent JSONB. **Templates write every pattern in full and keep `loop: false`** — they never lean on the resolver's loop expansion.
- `LYRIC_STYLES` = templates sharing the Lyrics-track contract (`lyricFlow`); switching styles is just `applyTemplate`, which carries the transcribed words across (`utils/multiStyleApply.ts`). Styles are excluded from the projects-page advertised list.
- `destination.ts` — where an applied template lands (scene-level `appliedTemplateId`; multi-scene projects can wear different templates per scene).
- Preview media for the pickers is generated by `scripts/generate-previews.mjs` (`npm run previews`), clips resolved via `src/components/templateClipUrl.ts`.
